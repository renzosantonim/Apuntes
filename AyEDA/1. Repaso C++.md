## BLOQUE 1: Tipos, Macros y el Preprocesador

En C++, antes de que el compilador lea tu código, pasa el **Preprocesador**. Es como un "editor de texto" automático que prepara el terreno.

### 1.1. Variables y Constantes

- **Tipado inamovible:** Toda variable en C++ tiene un tipo y no puede cambiarlo durante la ejecución. La declaración general es: `<TIPO> <NOMBRE> [=<VALOR>];`.
    
- **Inicialización:** Es mejor inicializar las variables tan pronto como sea posible.
    
- **Punteros constantes:** Existen errores de compilación específicos si tienes un puntero constante e intentas modificar su contenido o incrementar el puntero.
    

### 1.2. ¿Qué es exactamente una Macro (`#define`)?

Imagina que el `#define` es una función de "buscar y reemplazar" de Word. Las constantes se pueden definir tanto con el comando `const` como con `#define`.

- **Funcionamiento:** Si pones `#define PI 3.14`, el preprocesador busca la palabra `PI` en todo tu archivo y la cambia por `3.14` **antes** de compilar. Una macro es un fragmento de código con un identificador.
    
- **El peligro:** Como es un simple cambio de texto, no tiene tipo de dato. Si cometes un error, el compilador te dará un error en la línea donde usaste `PI`, pero no te dirá por qué.
    
- **Macros con argumentos:** Se pueden hacer "mini-funciones" como `#define CUADRADO(x) ((x)*(x))`. Es rápido, pero peligroso si no usas bien los paréntesis.
    

### 1.3. Alias de Tipos: `typedef` vs `using`

Sirven para dar nombres cortos a tipos de datos largos.

- **`typedef` (Estilo antiguo):** Se lee de derecha a izquierda. `typedef int Entero;` dice que `Entero` ahora significa `int`.
    
- **`using` (Estilo moderno/C++11):** Es mucho más claro. `using Clave = int;`. Es como una asignación: "Clave es igual a int".
    
- **En el examen:** Se usa mucho para que el código de los árboles o listas sea legible. Por ejemplo, en lugar de escribir `std::vector<Nodo<T>*>`, usas un alias como `using ListaHijos = std::vector<Nodo<T>*>`.

## BLOQUE 2: Constantes y Referencias (Seguridad y Velocidad)

### 2.1. El mundo de `const`

`const` es una promesa que le haces al compilador: "Este valor no va a cambiar".

- **En variables:** `const int limite = 100;`. Si intentas hacer `limite = 200;`, el código no compila.
    
- **En métodos de clase:** Esto cae siempre. `int obtenerDato() const { ... }`. Ese `const` al final significa que la función **solo lee**. Si intentas modificar un atributo de la clase dentro de esa función, te dará error.
    
- **Tip de examen:** Los profesores suelen poner métodos casi iguales pero uno con `const` y otro no. Para C++, son funciones distintas.
    

### 2.2. Paso de Parámetros y Referencias (`&`): El alias perfecto

A diferencia de un puntero (que guarda una dirección), una referencia **es** la propia variable pero con otro nombre.

- **No pueden ser nulas:** Una referencia siempre tiene que estar pegada a algo desde que nace. No existe "referencia a nada".
    
- **Paso por valor:** Se realiza una copia de la variable.
    
- **Paso por dirección:** Se mete un `(&var)` para la función porque lo que la función espera es un puntero, no un valor.
    
- **Eficiencia en funciones (Paso por referencia):** Si pasas un objeto grande (como un vector) a una función por valor, C++ hace una copia entera (lento y gasta memoria). Si lo pasas por **referencia constante** (`const Vector& v`), la función accede al vector original sin copiarlo (se trabaja directamente con la variable inicial), pero el `const` impide que lo rompa. Cuando un puntero devuelve una referencia, en realidad está devolviendo un puntero implícito a su valor de retorno.

## BLOQUE 3: Punteros y Memoria Dinámica (El Motor de C++)

Este es el mecanismo que mueve todas las estructuras de datos complejas (como los árboles y las listas enlazadas) y hace posible el polimorfismo.

### 3.1. ¿Qué es exactamente un puntero?

En C++, la memoria es como una calle larguísima con buzones. Cada buzón tiene un número (la **dirección de memoria**) y algo dentro (el **valor**).

- **Una variable normal:** Guarda el valor. (`int x = 5;`)
    
- **Un puntero:** Guarda la dirección de memoria de otro buzón. (`int* p;`)
    

Para trabajar con ellos necesitas dos operadores clave:

- **Ampersand (`&`) - "La dirección de":** Sirve para saber dónde vive una variable. Al copiar una dirección de memoria, se puede usar `int *p = &i` para guardar la dirección de la variable en el puntero.
    
    
    ```cpp
    int x = 5;
    int* p = &x; // p ahora guarda la dirección donde vive x (ej. 0x7ffee...)
    ```
    
- **Asterisco (`*`) - "Lo que hay en la dirección":** Se llama **desreferenciar**. Le dice a C++ que viaje a esa dirección y saque o modifique el valor que hay dentro.
    
    
    ```cpp
    std::cout << *p; // Imprime un 5
    *p = 10;         // Ahora x también vale 10
    ```
    

### 3.2. El operador Flecha (`->`)

Cuando tienes un puntero que apunta a un objeto complejo (como una clase `Nodo` o `Pieza`), no puedes usar un punto `.` para acceder a sus métodos o atributos. Tienes que usar la flecha `->`.

- **Qué hace:** Viaja a la dirección de memoria (hace el `*` por ti) y luego accede al miembro (hace el `.`).
    
- **Ejemplo de examen:** Si tienes un puntero `a` a un objeto, `a->f(4)` significa "ve al objeto al que apunta `a` y ejecuta su método `f` pasándole un 4".
	
    ```cpp
    // 1. Creamos un objeto normal de tipo Pieza
    Pieza miObjeto;
    
    // 2. Creamos un puntero 'a' que guarde la dirección de 'miObjeto'
    Pieza* a = &miObjeto;

    // --- FORMAS DE ACCEDER AL MÉTODO f(4) ---

    // Opción 1: Si tienes el objeto directamente, usas el PUNTO (.)
    miObjeto.f(4); 

    // Opción 2: Si tienes un puntero, podrías hacerlo "a mano"
    // Primero desreferencias con el (*) y luego usas el punto (.)
    // OJO: Los paréntesis son obligatorios aquí, lo cual hace que el código sea sucio.
    (*a).f(4);

    // Opción 3: LA FLECHA (->) - El atajo elegante
    // Hace exactamente lo mismo que la Opción 2, pero es mucho más fácil de leer.
    a->f(4);
    ```
    

### 3.3. El Campo de Batalla: Stack vs. Heap

Entender esto es vital para no perder los datos de tus árboles.

- **El Stack (Pila):** Es automático y rápido. Aquí van las variables locales de tus funciones. El problema es que al llegar al final de la función (`}`), **se destruye todo**. No puedes crear un nodo aquí porque desaparecería al terminar de insertarlo.
    
- **El Heap (Montículo):** Es memoria dinámica. Lo que creas aquí **vive para siempre** hasta que tú, manualmente, lo destruyas. Aquí es donde se construyen los árboles y las estructuras de AyEDA.
    

### 3.4. Controlando el Heap: `new` y `delete`

Son los comandos para pedir y devolver memoria dinámica.

- **`new`:** Busca hueco en el Heap, llama al constructor del objeto y **te devuelve un puntero** con su dirección.
    
    
    ```cpp
    // Crea un objeto B en el Heap y guarda su dirección en el puntero 'a'
    A *a = new B(5); 
    ```
    
- **`delete`:** Viaja a la dirección que le indiques, llama al destructor del objeto para limpiarlo y libera el hueco de memoria. Si no haces esto, la memoria se queda bloqueada para siempre (Fuga de Memoria o _Memory Leak_).
    
    
    ```cpp
    delete a; 
    ```
    

### 3.5. Punteros y Polimorfismo (La conexión final)

La razón por la que estudiamos punteros en esta asignatura es porque **el polimorfismo solo funciona a través de punteros o referencias**. C++ necesita la flexibilidad del Heap para que un puntero de tipo "Padre" (`A*`) pueda apuntar a un objeto de tipo "Hijo" (`new B()`), y decidir en tiempo de ejecución qué método `virtual` debe ejecutar.

## BLOQUE 4: Herencia y Polimorfismo (El núcleo de AyEDA)

Es la capacidad de crear jerarquías de clases. Los modificadores de acceso principales son `public`, `private` y `protected`. Los operadores en C++ actúan como funciones mediante `operator`.

### 4.1. Herencia: "Es un"

Si la clase `B` hereda de `A` (`class B : public A`), decimos que "B es un A".

- **Orden de construcción:** Esto es una pregunta clásica de examen. Los constructores no se heredan, pero se llaman de manera automática a partir de la clase derivada. Para construir un Hijo, **primero** tiene que existir el Padre. C++ llama al constructor de `A` y luego al de `B`.
    
- **Orden de destrucción:** Al revés. Primero se destruye lo último que se creó. Primero el destructor de `B` y luego el de `A`.
    
- **Controlando la herencia (`final` y `override`):** - En la herencia, se puede limitar la misma utilizando el método `final`, lo cual impide que una clase derivada sobreescriba un método virtual. Si se intenta heredar de una clase marcada como "final", el compilador arrojará el error _"a final class cannot be used as a base class"_.
    
    - El comando `override` le indica al compilador de la clase derivada que debe sobreescribir el comportamiento del método de la clase base. Si no se emplea el `override`, el comportamiento es exactamente equivalente, pero evita errores tipográficos.
        

### 4.2. Polimorfismo: La flexibilidad

Es cuando un puntero de tipo "Padre" apunta a un objeto "Hijo" (`A* obj = new B;`). Esto te permite tratar a muchos objetos distintos (Círculos, Cuadrados) como si fueran lo mismo (Formas). Esto se emplea para lograr polimorfismo en tiempo de ejecución. Desde la clase base se puede usar la versión redefinida del método.

### 4.3. La palabra mágica `virtual`

Sin `virtual`, C++ es "estático": mira el tipo del puntero y ejecuta esa función. Con `virtual`, C++ es "dinámico": mira qué objeto hay realmente en la memoria y ejecuta su función. Los métodos virtuales aseguran que se esté usando la versión correcta de un método sobre un objeto. La sobrecarga y redefinición consisten en el proceso de volver a definir en una clase derivada un método que ya fue definido en una clase base.

- **¡PELIGRO! Destructores Virtuales:** Destruir un objeto de una clase derivada utilizando un puntero de una clase base da lugar a un comportamiento indefinido (fugas de memoria), por lo que la clase debe tener un destructor virtual. Si se declara un destructor virtual, se debe implementar porque los destructores no serán sobreescritos en las clases derivadas, sino que serán invocados en orden inverso.
    
- **Métodos Virtuales Puros:** Se escriben como `virtual void func(<params>) = 0;`.
    
- **Clases Abstractas:** El objetivo de una clase abstracta es proporcionar una clase base adecuada a todas las que hereden de ella. Si una clase tiene al menos un método virtual puro, se vuelve abstracta (una clase virtual pura). **No puedes crear objetos con `new` de esa clase**, al intentar instanciar un objeto se generarán errores de compilación. Solo sirve para que otras hereden de ella. Una clase dejará de ser virtual pura tan pronto como todos sus métodos virtuales puros sean redefinidos con métodos reales. Una clase se convierte en abstracta también si tiene un destructor virtual puro.

```cpp
#include <iostream>
using namespace std;

// Clase Base Abstracta (Padre)
class A {
public:
    virtual void f() = 0; // Método virtual puro -> Hace que 'A' sea abstracta
};

// Clase Derivada Concreta (Hijo)
class B : public A {
public:
    void f() override { // Redefinimos el método con uno real
        cout << "Ejecutando f desde la clase Hijo (B)" << endl;
    }
};

int main() {
    // ESTO SÍ ES POSIBLE:
    // El puntero es de tipo Padre (A*), pero el objeto real creado en memoria es Hijo (B).
    A* obj = new B; 

    obj->f(); // Imprimirá: "Ejecutando f desde la clase Hijo (B)"

    delete obj;
    return 0;
}
```

### ¿Por qué usar un puntero del Padre para un objeto del Hijo? (`A* obj = new B;`)

A esta técnica se le conoce como **Upcasting** y es la herramienta principal para lograr el **polimorfismo en tiempo de ejecución**. Aunque podemos usar directamente `B* obj = new B;`, usar el puntero de la clase base nos da una ventaja gigante: **la flexibilidad de tratar objetos diferentes como si fueran iguales**.

**Usamos `A* obj = new B;` principalmente para dos cosas:**

- **Crear colecciones mixtas:** Permite guardar diferentes tipos de objetos derivados (Hijos) dentro de un mismo _array_ o lista del tipo base (Padre).
    
- **Reutilizar código:** Permite crear funciones genéricas que reciban al Padre por parámetro (`void curar(Padre* p)`). Esta única función servirá para cualquier tipo de Hijo presente o futuro, ahorrándonos escribir una función por cada clase derivada.
    
```cpp
// 1. Clase Base Abstracta (Padre)
class Enemigo {
public:
    Enemigo(string n, int s) : nombre(n), salud(s) {}

    // Método virtual puro: obliga a los hijos a implementarlo y hace la clase abstracta
    virtual void atacar() = 0; 
    
    // IMPORTANTE: Destructor virtual. Obligatorio al usar polimorfismo con new/delete
    virtual ~Enemigo() { cout << "Destruyendo Enemigo..." << endl; }
    
    string nombre;  // Esto debería ser protected
    int salud;      
};

// 2. Clases Derivadas (Hijos)
class Orco : public Enemigo {
public:
    Orco() : Enemigo("Orco", 100) {}
    void atacar() override { cout << nombre << " ataca con un hacha." << endl; }
    ~Orco() override { cout << "Destruyendo Orco..." << endl; }
};

class Dragon : public Enemigo {
public:
    Dragon() : Enemigo("Dragón", 500) {}
    void atacar() override { cout << nombre << " escupe fuego." << endl; }
    ~Dragon() override { cout << "Destruyendo Dragón..." << endl; }
};

// 3. FUNCIÓN GENÉRICA (Reutilización de código)
// ¡La magia! Recibe un puntero al Padre, por lo que acepta a CUALQUIER Hijo.
// No necesitamos hacer un curar(Orco* o) y otro curar(Dragon* d).
void curar(Enemigo* e) {
    e->salud += 50;  // Al salud ser protected, esto debería ser con un getter.
    cout << "[CURACIÓN] La salud de " << e->nombre << " sube a " << e->salud << endl;
}

int main() {
    cout << "--- CREANDO LA HORDA ---" << endl;
    // Array de punteros tipo Padre (Enemigo) que guarda objetos Hijo
    Enemigo* horda[2];
    horda[0] = new Orco();
    horda[1] = new Dragon();

    cout << "\n--- ATAQUE MASIVO (Colecciones Mixtas) ---" << endl;
    // Gracias al polimorfismo, llama al método correcto de cada hijo
    for(int i = 0; i < 2; i++) {
        horda[i]->atacar(); 
    }

    cout << "\n--- CURANDO A LA HORDA (Función Genérica) ---" << endl;
    // Pasamos diferentes tipos de objetos a la misma función
    curar(horda[0]); // Curamos al Orco
    curar(horda[1]); // Curamos al Dragón

    cout << "\n--- LIMPIEZA DE MEMORIA ---" << endl;
    // Al usar delete, como el destructor es virtual, se llama primero 
    // al destructor del Hijo y luego al del Padre de forma segura.
    delete horda[0];
    delete horda[1];

    return 0;
}
```

Aplicación a un caso de programa real C++, aplicando encapsulación.

```cpp
class Enemigo {
 public:
    Enemigo(string n, int s) : nombre(n), salud(s) {}

    virtual void atacar() = 0; 
    virtual ~Enemigo() { cout << "Destruyendo Enemigo..." << endl; }

    // MÉTODOS DE ACCESO (Getters y acciones)
    // Son la única forma de que el mundo exterior interactúe con las 
    // variables ocultas
    string getNombre() { 
        return nombre; 
    }

    void recibirCuracion(int cantidad) {
        salud += cantidad;
        cout << "[CURACIÓN] La salud de " << nombre << " sube a " << salud;
    }
// Usamos protected: oculto para el exterior, pero accesible para los Hijos
 protected:
    string nombre;
    int salud;
};

class Orco : public Enemigo {
public:
    Orco() : Enemigo("Orco", 100) {}
    void atacar() override { cout << nombre << " ataca con un hacha." << endl; }
    ~Orco() override { cout << "Destruyendo Orco..." << endl; }
};

class Dragon : public Enemigo {
public:
    Dragon() : Enemigo("Dragón", 500) {}
    void atacar() override { cout << nombre << " escupe fuego." << endl; }
    ~Dragon() override { cout << "Destruyendo Dragón..." << endl; }
};

// La función genérica ahora usa los métodos públicos, respetando la encapsulación
void curar(Enemigo* e) {
    // Ya no hacemos e->salud += 50. Le pedimos al objeto que se cure a 
    // sí mismo.
    e->recibirCuracion(50); 
}

int main() {
    Enemigo* horda[2];
    horda[0] = new Orco();
    horda[1] = new Dragon();

    for(int i = 0; i < 2; i++) {
        horda[i]->atacar(); 
    }

    curar(horda[0]); 
    curar(horda[1]); 

    delete horda[0];
    delete horda[1];

    return 0;
}
```

## BLOQUE 5: Plantillas (Templates) - Código Genérico

Son elementos fundamentales de la programación genérica. La programación genérica está centrada en los algoritmos y en los tipos de datos. Existen dos tipos de plantillas en C++: de funciones y de clases.

### 5.1. ¿Por qué usamos Plantillas?

Imagina que haces un árbol para guardar números (`int`). Si mañana quieres guardar nombres (`string`), tendrías que copiar y pegar todo el código. Las plantillas permiten que el tipo de dato sea una variable (normalmente llamada `T` o `Key`).

### 5.2. Sintaxis y Especialización

- **Declaración:** `template <class T> class Nodo { T dato; };`.
    
- **Especialización Total:** A veces quieres que para un tipo concreto (como `bool`) el código funcione distinto. Se usa `template <> class Nodo<bool> { ... };`.
    
- **En el examen:** Te pedirán definir estructuras como `NTree<class Key, int N>`, donde `Key` es el tipo y `N` es un número fijo (como el número de hijos).
    
```cpp
// 1. PLANTILLA BÁSICA DE CLASE (Encapsulada)
template <class T>
class Nodo {
 public:
    Nodo(T dato) : dato_(dato) {}. // Constructor
    
    // Getter para acceder al dato de forma segura
    T getDato() const {
        return dato_;
    }

    // Setter por si queremos modificarlo después
    void setDato(T dato) {
        dato_ = dato;
    }
    
    void mostrar() const {
        cout << "Nodo genérico contiene: " << dato_ << endl;
    }
    
 private:
    T dato_;
};

// 2. ESPECIALIZACIÓN TOTAL (Encapsulada)
template <>
class Nodo<bool> {
 public:
    Nodo(bool dato) : dato_(dato) {}
    
    bool getDato() const { return dato_; }
    void setDato(bool dato) { dato_ = dato; }
    
    void mostrar() const {
        cout << "Nodo booleano contiene: " << (dato_ ? "VERDADERO" : "FALSO") 
             << " (¡Usando código especializado!)" << endl;
    }
 private:
    bool dato_;
};

// 3. PLANTILLA DE EXAMEN (Encapsulada)
template <class Key, int N>
class NTree {
 public:
    NTree(Key raiz) : raiz_(raiz) {}
    
    Key getRaiz() const {
        return raiz_;
    }

    // Método seguro para añadir o modificar un hijo en una posición específica
    void setHijo(int indice, Key valor) {
        if (indice >= 0 && indice < N) {
            hijos_[indice] = valor;
        } else {
            cout << "Error: Índice fuera de rango." << endl;
        }
    }

    // Método seguro para obtener un hijo
    Key getHijo(int indice) const {
        if (indice >= 0 && indice < N) {
            return hijos_[indice];
        }
        throw out_of_range("Índice fuera de rango"); // Usando excepciones
    }
    
    void mostrarInfo() const {
        cout << "NTree creado: Raíz '" << raiz_ << "' con un máximo de " << N
        << " hijos." << endl;
    }
 private:
    Key raiz_;
    Key hijos_[N];
};

int main() {
    cout << "--- 1. PROBANDO PLANTILLA BÁSICA ---" << endl;
    Nodo<int> nodoNumero(42);
    // nodoNumero.dato_ = 50; // ERROR: Es privado.
    nodoNumero.setDato(50);  // CORRECTO: Usamos el setter.
    nodoNumero.mostrar();

    cout << "\n--- 3. PROBANDO NTREE (Tipo Examen) ---" << endl;
    NTree<char, 3> miArbol('A');
    miArbol.setHijo(0, 'B'); // Asignamos un hijo de forma segura
    miArbol.mostrarInfo();
    
    cout << "El primer hijo es: " << miArbol.getHijo(0) << endl;

    return 0;
}
```

## BLOQUE 6: Excepciones (Gestión de Crisis)

Hay tres formas de gestionar errores: finalizar el programa, devolver un código de error o lanzar excepciones. Se debe evitar la finalización abrupta del programa. El uso de excepciones se recomienda en caso de querer expandir un mensaje de error.

- **Errores de compilación:** Están relacionados con la sintaxis o la semántica, y el compilador se encarga de ellos.
- **Errores en tiempo de ejecución:** Ocurren durante la ejecución del código binario, el compilador no los detecta y hacen impredecible el resultado de la ejecución.

### 6.1. El flujo `try`, `throw`, `catch`

Es como un sistema de alarma. Las palabras `try` y `catch` siempre van emparejadas para la propagación del código de error.

1. **`try`**: "Intenta ejecutar este código". (Para disponer un código bajo análisis en busca de errores).
    
2. **`throw`**: Si algo sale mal (ej: un índice fuera de rango), lanzas un objeto de error (la alarma).
    
3. **`catch`**: Si se lanza una alarma, el programa salta aquí para ver cómo arreglarlo o avisar al usuario. La captura por referencia es preferible y se debe evitar la captura por valor.

### 6.2. Reglas Avanzadas de Excepciones (¡Nuevo!)

- **Múltiples catch:** Si el bloque `try` puede generar varios tipos de excepciones, se deben agregar múltiples cláusulas `catch`.
    
- **El Recogetodo (`catch(...)`):** Para capturar todo tipo de excepciones, se utilizan los puntos suspensivos `...` como parámetro de captura y debe colocarse como el último `catch`.
    
- **Relanzar (`throw;` vacío):** Si no se puede manejar una excepción de forma inmediata, lo mejor es usar `throw` dentro del `catch`. Un `throw` sin argumentos devuelve la misma excepción que ya estaba atrapada. _Advertencia:_ Si lanzas un `throw` vacío y no hay un bloque `try-catch` más arriba que lo recoja, el programa colapsará dando un error en tiempo de ejecución.
    
- **Constructores y Destructores:** Como los constructores no tienen tipo de retorno, sus fallos deben ser gestionados mediante excepciones. En caso de error, una buena práctica es poner el objeto en un estado "zombie" mediante un bit de estado interno y comprobar si el objeto es válido usando una función miembro de inspección. Los destructores se suelen llamar durante el desenrollado de la pila (_stack unwinding_), cuando la excepción se ha generado pero aún no se ha manejado. Es mala idea que un destructor cause una excepción; si ocurre, reemplaza a la excepción anterior o debe ser ignorada.

### 6.3. Excepciones Personalizadas y Librería Estándar

La biblioteca `std` de C++ proporciona la librería `exception`. Contiene excepciones como `bad_alloc` (lanzada por `new` cuando no puede asignar la cantidad de memoria solicitada), `out_of_range` (al salir del rango de un vector) e `invalid_argument`. Puedes crear tus propios tipos de error heredando de `std::exception` (sobreescribiendo las funcionalidades del comando exception).

- **Ejemplo:** En el examen de Ajedrez, si el Rey no tiene el movimiento programado, se lanza una excepción de tipo `Not_yet_implemented`. Esto evita que el programa se cuelgue y permite al programador saber exactamente qué falta por hacer.
    
```cpp
#include <exception> // Librería base de excepciones de C++
#include <stdexcept> // Para excepciones estándar como out_of_range e
                     // invalid_argument

// 1. EXCEPCIÓN PERSONALIZADA (Tipo Examen)
// Creamos nuestra propia excepción heredando de std::exception
class Not_yet_implemented : public std::exception {
public:
    // Sobreescribimos el método what() que devuelve el mensaje de error
    // 'noexcept' indica que este método en sí mismo no lanzará excepciones
    const char* what() const noexcept override {
        return "Error 404: El movimiento del Rey aún no está programado.";
    }
};

// 2. CLASE QUE GENERA ERRORES
class Ajedrez {
public:
    void moverRey(int x, int y) {
        // Simulamos que el programador olvidó programar esto
        // Lanzamos (throw) nuestra alarma personalizada
        throw Not_yet_implemented(); 
    }

    void accederHistorial(int turno) {
        vector<string> historial = {"Peón e4", "Caballo f3"};
        
        // Si piden un turno que no existe, lanzamos excepción estándar
        if (turno < 0 || turno >= historial.size()) {
            // out_of_range se lanza cuando nos salimos de los límites
            throw out_of_range("Turno fuera de rango en el historial.");
        }
        cout << "Movimiento: " << historial[turno] << endl;
    }

    void procesarConexion() {
        try {
            // Simulamos un error grave de red
            throw invalid_argument("Datos de conexión corruptos.");
        } catch (const invalid_argument& e) {
            cout << "[Log Interno]: Fallo detectado -> " << e.what() << endl;
            cout << "[Log Interno]: Relanzando excepción hacia arriba...\n";
            // throw sin argumentos vuelve a lanzar la misma excepción atrapada
            throw; 
        }
    }
};

// 3. MAIN: BLOQUE TRY - CATCH
int main() {
    Ajedrez partida;

    cout << "--- CASO 1: MÚLTIPLES CATCH Y RECOGETODO ---" << endl;
    
    // try: "Intenta ejecutar esto bajo análisis"
    try {
        cout << "Intentando acceder al turno 5..." << endl;
        partida.accederHistorial(5); // Lanzará out_of_range
        
        // ¡OJO! Si la línea anterior lanza error, el código salta inmediatamente
        // al catch. Esta siguiente línea NUNCA se llegará a ejecutar.
        partida.moverRey(2, 2); 

    } 
    // Múltiples bloques catch capturando por REFERENCIA (const &)
    catch (const Not_yet_implemented& e) {
        cout << "¡Excepción Personalizada Capturada! " << e.what() << endl;
    } 
    catch (const out_of_range& e) {
        // La biblioteca std nos proporciona out_of_range
        cout << "¡Excepción Estándar Capturada! " << e.what() << endl;
    } 
    // El Recogetodo (...): Atrapa cualquier cosa que no sea de los tipos
    // anteriores. DEBE colocarse como el último catch.
    catch (...) {
        cout << "Error Crítico Desconocido. Abortando misión." << endl;
    }

    cout << "\n--- CASO 2: RELANZAMIENTO DE EXCEPCIONES ---" << endl;
    
    try {
        partida.procesarConexion(); // Relanzará un error desde dentro
    } catch (const exception& e) { // exception base captura cualquier hija
        cout << "Main atrapó la excepción relanzada: " << e.what() << endl;
    }
    return 0;
}
```

## BLOQUE 7: Píldoras Teóricas de Examen (Las Trampas del Test)

### 7.1. Conversión de Tipos (Typecasting)

La conversión es un operador especial que fuerza a un tipo de dato a convertirse en otro. ¿Es posible cambiar el tipo de una variable en C++ una vez definida? La respuesta es **Sí, mediante el uso de typecasting**.

- **Cómo funciona:** Le dices al compilador que trate temporalmente una variable como si fuera de otro tipo.
    
- **En C++ moderno:** Aunque existe el casting estilo C (`(int)miFloat`), C++ usa operadores específicos y más seguros:
    
    - `static_cast<type>(expr)`: Realiza un cambio no polimórfico (ej. de `float` a `int`).
        
    - `dynamic_cast<type>(expr)`: Realiza una conversión en tiempo de ejecución; si no es posible, el resultado queda como `null`. Se emplea para convertir de forma dinámica y segura hacia abajo (o hacia arriba) en una jerarquía de clases, de un puntero de clase base a un puntero de clase derivada. **Para usarlo, es importante que la clase contenga al menos un método virtual.**
        
    - `const_cast<type>(expr)`: Se emplea para sobreescribir un cast (quitar o poner constantes).
        
    - `reinterpret_cast<type>(expr)`: Cambia un puntero a cualquier otro tipo de puntero.
        
- **El operador `typeid` :** Es un operador que permite consultar información sobre un tipo o comprobar si dos objetos son del mismo tipo en tiempo de ejecución. Su sintaxis puede ser `typeid(type)` o `typeid(expression)`.

### 7.2. Constructores Privados (`private`)

Normalmente, los constructores siempre se ponen en la zona `public` para poder crear objetos. Pero, ¿qué pasa si pones el constructor de una clase como `private`?

- **Consecuencia:** **No se pueden crear objetos de dicha clase** desde fuera de ella. Si intentas hacer `MiClase obj;` o `new MiClase();` en el `main`, el compilador te dará un error diciendo que el constructor es inaccesible.
- **¿Para qué sirve?:** Se usa en patrones de diseño avanzados (como el _Singleton_) donde quieres asegurarte de que solo exista **una única instancia** de esa clase en todo el programa. Otra forma de limitar la creación es definir el constructor de la clase (base o derivada) como `private` e incluir un método `static` para crear objetos.
### 7.3. La promesa de `noexcept`

En el bloque de excepciones vimos que C++ te permite lanzar errores. La palabra clave `noexcept` sirve exactamente para lo contrario. El modificador `noexcept` designa a una función destinada a no lanzar ninguna excepción, lo que permite ciertas optimizaciones del compilador.

- **Propósito:** Se pone al final de la declaración de una función para **indicar que esa función no lanza una excepción** bajo ninguna circunstancia.
    ```
    int sumarSeguro(int a, int b) noexcept {
        return a + b;
    }
    ```
