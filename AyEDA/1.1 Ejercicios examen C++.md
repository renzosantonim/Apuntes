### 1. Indica y justifica cuál es el resultado que aparece por pantalla. ###

```cpp
class A {
private:
    int a_;
public:
    A(int x) : a_(x) {}
    virtual int f(int x) { return g(x * x); }
    virtual int g(int x) const { return x * a_; }
};

class B : public A {
private:
    int b_;
public:
    B(int x = 2) : A(x * x), b_(x) {}
    int f(int x) const { return g(x + b_); }
};

class C : public B {
public:
    int f(int x) { return A::f(x + x); }
    int g(int x) const { return x; }
};

int main() {
	B *a = new B;
	std::cout << a->f(4) << std::endl;
	A *b = new B(5);
	std::cout << b->f(3) << std::endl;
	A *c = new C;
	std::cout << c->f(2) << std::endl;
	return 0;
}
```

### Primer bloque ###
```cpp
B *a = new B;
std::cout << a->f(4) << std::endl;
```

**1. Construcción del objeto en el Heap (`new B`):**

- Llamamos al constructor de `B` sin pasarle parámetros. Como tiene un valor por defecto `x=2`, es como hacer `B(2)`.
    
- _Regla de Herencia:_ ¡Primero se construye el Padre! El constructor de `B` llama al de `A` pasándole `(x * x)`, es decir, `(2 * 2) = 4`. Así que en el Padre, **`a_ = 4`**.
    
- Luego se construye el Hijo: inicializa su atributo `b_` con `x`. Así que en el Hijo, **`b_ = 2`**.
    

**2. La llamada al método (`a->f(4)`):**

- El puntero `a` es de tipo `B*`. El compilador busca la función `f` dentro de `B`.
    
- Encuentra `int f(int x) const`. Y aquí está la genialidad del profesor: ¿Ese método está sobreescribiendo al método `f` de `A`? **¡NO!** * Como la de `B` tiene un `const` al final y la de `A` no, C++ las considera firmas completamente distintas. La de `B` "oculta" a la de `A` (por eso en los apuntes veíamos que el `override` te salva la vida aquí).
    
- Se ejecuta `B::f(4)`:
    
    - Devuelve `g(x + b_)` => `g(4 + 2)` => **`g(6)`**.
        
- ¿A qué `g` llama? Como `B` no tiene ninguna función `g`, C++ sube y busca en el Padre (`A`).
    
- Se ejecuta `A::g(6) const`:
    
    - Devuelve `x * a_` => `6 * 4` => **`24`**.

**Resultado que sale por pantalla:** `24`

### Segundo bloque ###
```cpp
A *b = new B(5);
std::cout << b->f(3) << std::endl;
```
#### Paso 1: Construcción en el Heap (`new B(5)`)

Al reservar memoria dinámica para el objeto, se activa la herencia en cascada. El parámetro inicial es `x = 5`.

- **Fase del Padre (`A`):** Por la lista de inicialización de `B` (`: A(x * x)`), se invoca al constructor de `A` pasándole el cuadrado del parámetro. Por tanto, `A` recibe `5 * 5 = 25`. El atributo privado del padre queda guardado como **`a_ = 25`**.

- **Fase del Hijo (`B`):** Tras inicializarse el padre, el hijo guarda el valor original en su atributo. El atributo privado del hijo queda guardado como **`b_ = 5`**.
#### Paso 2: Resolución del Enlace Dinámico (Polimorfismo)

Se invoca al método `b->f(3)` empleando un puntero de tipo clase base (`A*`) que apunta a un objeto real de la clase derivada (`B`).

- **La trampa de la firma:** C++ busca si el objeto real (`B`) ha sobreescrito el método `virtual int f(int x)` del padre. Al revisar la clase `B`, encontramos `int f(int x) const`. El modificador `const` cambia completamente la firma del método, por lo que **no existe sobreescritura (override)**; el método de `B` simplemente oculta al de `A`.
    
- **Resolución:** Al no estar sobreescrito el método virtual, C++ se ve obligado a ejecutar de forma estática la versión de la clase del puntero, es decir, **`A::f(3)`**.
#### Paso 3: Flujo de Ejecución y Resultado

1. Entramos en `A::f(3)`, que ejecuta la instrucción `return g(x * x);`. Como el parámetro recibido es `3`, calcula `3 * 3 = 9` e invoca internamente a **`g(9)`**.
    
2. Para resolver la función `g`, C++ busca si el objeto real (`B`) implementa su propio método `g`. Al comprobar que `B` no tiene ningún método llamado `g`, hereda directamente el del padre .
    
3. Se ejecuta **`A::g(9) const`**, cuya lógica es `return x * a_;`.
    
4. Sustituyendo los valores almacenados en memoria: `9` (parámetro actual) `* 25` (atributo `a_` calculado en el paso 1) `= 225`.

**Resultado que sale por pantalla:** `225`

### Tercer bloque ###
```cpp
std::cout << c->f(2) << std::endl;
return 0;
```

**Paso 1: Construcción en cascada**

Creamos un objeto `C` sin parámetros.

- `C` llama al constructor de `B` sin parámetros, que toma el valor por defecto `x = 2`.
    
- `B` llama al constructor de `A` pasándole `x * x` (4). Así que en el Abuelo, **`a_ = 4`**.
    
- En el Padre, **`b_ = 2`**.
    

**Paso 2: Sobreescritura válida**

Al llamar a `c->f(2)`, C++ busca en la clase real `C` si ha sobreescrito el método virtual `f` (sin `const`). ¡Sí lo ha hecho! Entramos en `C::f(2)`.

**Paso 3: Forzar la subida y la regla del `this` virtual**

1. El código de `C::f(2)` fuerza explícitamente a ignorar el polimorfismo con la instrucción `return A::f(2 + 2);`.
    
2. Saltamos al Abuelo y ejecutamos `A::f(4)`. Su código nos dice que hagamos `return g(16)`.
    
3. **Punto clave:** Esa llamada equivale a `this->g(16)`. Como `g` es virtual, C++ vuelve a mirar al objeto real en el Heap (que es un `C`).
    
4. Como `C` ha sobreescrito `g` correctamente (`int g(int x) const`), se ejecuta `C::g(16)`.
    
5. El código de `C::g` simplemente devuelve el parámetro recibido. Resultado: **16**.

**Resultado que sale por pantalla:** `16`
