## 1. Idea intuitiva
En un **cifrado en flujo**, el mensaje no se cifra por bloques completos como en AES, sino combinándolo con una **secuencia cifrante** que se va generando poco a poco.

La idea básica es:
- partes de una **semilla** o clave
- un **generador pseudoaleatorio** produce una secuencia de bits
- esa secuencia se combina con el mensaje mediante **XOR**
- el resultado es el texto cifrado

Eso aparece de forma explícita en la teoría: el emisor usa una semilla secreta y un generador pseudoaleatorio para producir una secuencia binaria, y luego hace XOR bit a bit con el texto en claro. Para recuperar el original, se vuelve a hacer la misma operación con la misma secuencia.

## 2. Conceptos mínimos

### Secuencia cifrante
Es la secuencia de bits que el algoritmo genera a partir de la clave o semilla.
### Semilla
Es el valor inicial secreto que se introduce en el generador.
### Generador pseudoaleatorio
Es un algoritmo determinista que, a partir de una semilla, produce una secuencia que “parece aleatoria”.

## 3. Relación con Vernam

Vernam ya te daba esta idea:

![[Pasted image 20260404100712.png|127]]

La diferencia es que en Vernam puro la clave tiene la misma longitud que el mensaje, mientras que en los cifrados en flujo modernos normalmente:

- no usas una clave tan larga como el mensaje
- usas una **clave corta o semilla**
- el generador produce a partir de ella una **secuencia larga**

Por eso, conceptualmente, un cifrado en flujo moderno se puede ver como una versión práctica de la idea de Vernam.

## 4. Funcionamiento paso a paso

### En el emisor
1. Se toma una clave o semilla.
2. Se introduce en el generador pseudoaleatorio.
3. El generador produce una secuencia cifrante.
4. Se hace XOR entre esa secuencia y el mensaje original.
5. Sale el texto cifrado.
### En el receptor
1. Se toma la misma clave o semilla.
2. Se genera exactamente la misma secuencia cifrante.
3. Se hace XOR entre esa secuencia y el texto cifrado.
4. Se recupera el mensaje original.

Esto solo funciona si ambos lados generan **exactamente la misma secuencia**.

## 5. Qué algoritmos tuyos entran aquí

Dentro del temario de la asignatura, pertenecen a este bloque:
- ChaCha20
- LFSR / RDRL
- GPS L1 C/A
- SNOW 3G 

Todos comparten la idea de “generar secuencia y combinarla con el mensaje”, aunque luego cada uno tenga una estructura distinta.

## 6. Diferencia básica con cifrado en bloque

Se dice que:
- en **bloque**, el algoritmo se aplica sobre cada bloque del mensaje usando la misma clave
- en **flujo**, el algoritmo se aplica sobre cada bit usando los distintos bits de la secuencia de clave 

Quédate con esta diferencia simple:
### Cifrado en flujo
- trabaja con una secuencia cifrante
- suele usar XOR
- opera de forma continua o bit a bit
### Cifrado en bloque
- divide en bloques
- aplica rondas y transformaciones internas
- depende del bloque completo

## 7. Ventajas y desventajas básicas

### Ventajas del cifrado en flujo
- alta velocidad de cifrado
- no propaga errores
- sí oculta información estructurada 
### Desventajas del cifrado en flujo
- baja difusión
- vulnerable a alteraciones

### Nota:
- ***baja difusión*** = un cambio pequeño en la entrada produce un cambio pequeño y localizado en la salida
- ***alta difusión*** = un cambio pequeño en la entrada se reparte por muchas posiciones de la salida
